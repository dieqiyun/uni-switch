# Codex 思考强度自动修复 · 0.5.9

每次通过 uni-switch 写入 Codex 配置，自动检测并修复思考强度菜单缺项。不再提供手动修复按钮，也不依赖旧供应商的 `codexOptions.repairReasoningLevels` 标记。

## 自动处理范围

- 添加并使用、使用供应商、保存并使用，以及同步当前 Codex 连接信息。
- 模型同步确认、默认模型选择、逐模型上下文确认、批量模型配置确认。
- Fast 快捷开关专用写入，同时保留已经应用的连接、模型和上下文，不顺带应用待确认的密钥或模型修改。
- 同一模型设置再次确认时仍检测。已经完整且没有文件变化时，不增加配置版本或触发新的重启提示。

未使用供应商的修改只保存，下次使用时执行检测。名称、置顶、余额刷新等操作没有写入 Codex 配置，不触发修复。取消添加、编辑和模型草稿也不会写入文件。

## 修复内容

1. 在 `uni-switch-models.json` 中补齐每个模型的 `supported_reasoning_levels`：`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`、`ultra`。不重复添加，不改变当前选择的 `model_reasoning_effort`。
2. 在 `config.toml` 的 `[desktop]` 中补齐 `enabled-reasoning-efforts`。保留已有有效值和其它桌面偏好。旧供应商只有默认模型时，为默认模型创建目录，默认上下文256k，并写入 `model_catalog_json` 引用。

这里修复客户端的显示元数据。模型或网关是否实际支持对应强度仍由供应商决定，Codex桌面端自己的功能开关仍适用。

## 事务、冲突与恢复

修复加入现有配置文件事务，写完校验后才提交数据库。格式损坏、API字段变化或其它模型目录外部修改时，整个操作停止，不记录虚假的成功，也不部分写入。

仅标准强度项缺失可以自动补回；模型说明、已有强度说明、自定义项、上下文及其它元数据被外部修改时继续报冲突。Fast修复保留已有模型目录元数据。首次管理新增字段时捕获它们的原值，兼容没有开启旧修复标记的0.5.8管理记录。

“恢复原配置”还原接管前的显示偏好与模型目录，保留后续无关设置，不把自动修复再次写回恢复结果。

## 验证

后端回归覆盖旧供应商和共享Claude供应商无需开启修复、反复出现缺项后的模型/上下文/连接/Fast确认、无变化不增加版本、其它元数据冲突不写入、旧管理记录首次补齐和恢复原偏好。

原生验收通过隔离配置删除 `max` 和缩小显示列表，再使用普通Fast开关验证自动补回。真实Codex `app-server`读取模型目录与显示配置，并使用本机安装的桌面菜单过滤函数验证 `max` 可见。测试不操作正在运行的真实客户端，也不使用用户密钥。
