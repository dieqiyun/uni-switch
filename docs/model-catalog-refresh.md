# 模型同步移除下架项目（本地待发布）

> 本文记录此前的本地预览过程；这些改动现已纳入 0.5.17 开源版本。发布内容与许可见 CHANGELOG.md 和 docs/github-release.md。
本次沿用0.5.16本地版本，没有发布GitHub。保留当前的黑白应用标志、Claude彩色官方Logo与底部居中的蝶祈云紫色品牌入口。

## 问题与变化

之前的同步逻辑把最新响应与旧列表合并，额外追加旧列表中已启用但上游不再返回的模型。这些模型仍占用计数，界面显示“最新列表未包含”，并要求用户手工取消后才能保存。

现在成功同步后的模型集合只来自上游响应。旧的已启用或未启用模型，只要不再返回，均不出现在模型列表、搜索结果和本次计数里，其草稿上下文也移除。新增适用模型继续默认全选；仍在列表里的模型保留勾选状态与每模型上下文。

默认模型仍在且启用时保持原值；默认模型下架时优先使用仍存在的已启用模型，没有旧的可用选择时从新增模型中自动推荐。全部取消时不强行启用一个模型，确认保存仍要求至少一个适用模型。

请求失败、无权限、无有效模型或分页失败均不按“全下架”处理，保留原列表和配置。连接变化与迟到响应的保护逻辑继续保留。

## 保存与Codex读取

打开模型弹窗的同步结果先作为草稿。取消、Escape不会修改供应商或客户端文件。点击“保存并应用”后，当前Codex供应商的模型记录、`uni-switch-models.json`和`config.toml`默认模型一起更新；目录只包含最新仍启用的模型，下架项不会追加回来。未使用的供应商先保存，下次点击“使用”时应用。

保持已有的原子写入、外部冲突检测和失败回滚。Codex自己选择的模型只有仍在启用列表中才会保留；下架的选择改用新的默认值。思考强度与Fast偏好保留。每次实际写入仍自动修复思考强度显示并弹出重启提示，运行中的Codex重启后加载新列表。

此规则在完整添加/编辑与模型弹窗共用的`useConnectionDiscovery`中实现；删除了旧的缺失模型追加和要求手工取消的分支。

## 验证

130项前端、119项Rust测试通过（1项环境辅助按定义ignored）。TypeScript/Vite、Windows独立程序与NSIS安装包构建通过。模型/顶部/更新/品牌14组原生检查及23处Axe、协议回归6组原生及8处Axe均通过，页面运行错误为0。最终包与正式构建文件校验一致，正式EXE不含QA官网跳转记录或调试端口标记。

前端回归覆盖同步移除启用/未启用旧项、默认替代、上下文和取消项保留、失败保留、草稿取消、完整表单提交，以及五个旧模型全部下架后只提交四个新模型。

Rust回归覆盖当前Codex选中了下架模型的两种情况：默认模型本身下架，以及默认仍在但客户端所选模型下架。实际文件目录只保留新模型，配置默认值有效，保留思考强度/Fast，重开数据库再确认不会复活旧项。

原生QA在隔离数据与配置目录使用本地模拟上游。先返回五个模型，再完全替换成四个模型，检查弹窗只显示四个、取消无写入、保存并应用只写四个并提示重启。同步失败仍保留最新四个。

QA同时启动本机真实Codex的独立`app-server`，分别在替换前后调用`model/list`和`config/read`，核对返回模型集合与启用目录一致、默认模型仍有效。该验证不发推理请求、不操作当前运行中的桌面菜单，也不改用户真实客户端目录。
