# 切换提醒与 GitHub 远程更新

从 v0.5.21 起提供以下切换提醒和 GitHub 远程更新功能。

## 切换后的行为

实际写入配置后，原有的重启提示同时强调「切换后请新开对话」。旧 Codex 会话可以保留原模型与思考强度；重启后恢复旧会话也不保证采用全局新默认值。用户可选择稍后重启，程序不会替用户切换旧会话的参数。

Claude 未运行时，写入后展示配置已保存和新会话提示，无需执行不存在的重启。进程检测不确定时仍提示用户自行确认已打开的客户端。历史写入、取消草稿以及未造成文件变化的操作不产生新的写入提示。

软件离线教程与 GitHub 教程共用 `src/content/tutorial.json`。教程「日常切换 → 切换后怎么看使用记录」说明：供应商控制台用量是实际请求记录，本地默认配置不是实时会话或上游用量；历史记录不随切换改变。应用目前不提供读取上游请求日志的接口。

## 每次选择更新方式

点击左下角版本号或新版提醒后，查看版本和更新说明，选择：

- GitHub 手动下载：打开固定仓库的对应发布页，由用户下载和安装。
- 远程更新：应用重新查询 GitHub 最新正式版，确认仍是用户选择的版本，再下载本系统安装包。

更新检测不自动下载，方式不存入偏好。下载显示实际字节进度，支持取消，失败后可重新选择。下载期间弹窗不会被 Escape 或遮罩意外关闭。已校验待安装时可取消或关闭，再次打开可继续确认安装。

## 校验与安装

选择固定仓库、固定版本、固定系统对应的文件名；前端只能传版本和一次性任务标识，不能传执行地址或本地路径。下载只允许 GitHub 及其发行附件域的 HTTPS 跳转，不携带供应商凭据。

校验依据是 GitHub 附件的 sha256 digest，或同一发布的 SHA256SUMS.txt 中精确匹配的条目。必须同时匹配文件长度、SHA256 和安装包文件格式。发布附件须提供正数大小及校验依据；否则禁用远程更新。安装前再次计算缓存文件的哈希，缓存被修改则拒绝执行。此校验验证附件与 GitHub 发布的对应关系，不等同于平台代码签名或 Apple 公证。

校验通过后，用户仍需点击「安装更新」。

| 系统 | 确认后的行为 |
| --- | --- |
| Windows x64 | 启动 NSIS 安装向导，退出 uni-switch；用户完成向导后重新打开 |
| macOS Intel / Apple Silicon | 打开通用 DMG，用户退出旧版后拖入 Applications 完成替换 |
| Linux x64 DEB | 请求打开系统安装程序；权限和安装操作由系统处理 |
| Linux x64 AppImage 后备 | 打开下载目录，用户退出旧版后替换文件、设置执行权限并启动 |

安装不会修改客户端配置或替用户重启 Codex / Claude。uni-switch 退出时本地转换服务会暂停，界面明确提示先结束正在进行的请求。取消及失败缓存自动清理；已交给系统安装的附件保留在本次更新的临时目录，避免安装过程中提前删包。

## 发布要求

继续使用现有三平台发布流水线，无需另设升级服务器或签名密钥。现有发布脚本已经产生 SHA256SUMS.txt；应继续提供每个附件的真实大小，保持版本标签、附件文件名、校验条目与对应源码一致。没有合格产物的历史版本仅提供手动下载，不修改历史发布来开启功能。

## 验证入口

- 前端测试：每次选择、不自动下载、取消、安装确认、失败重选、无校验包降级。
- Rust 测试：GitHub digest 与清单两种路径、无供应商认证、损坏/截断/错误格式、缓存篡改、版本变化、取消中断、并发与重复安装、可信跳转域。
- scripts/qa-app-update-remote.mjs：隔离 Windows WebView2 和模拟 GitHub，覆盖切换提醒、手动入口、下载进度、取消、失败、新版本变化、安装确认与窄窗口无障碍。QA 构建只记录安装路径，不执行真实安装，也不退出真实应用。

本机测试不能代替 macOS/Linux 原生安装验证；对这些平台不声称已完成实机安装。
