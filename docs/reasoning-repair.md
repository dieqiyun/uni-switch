# 思考强度列表修复 · 0.3.5

> **0.5.9 最新行为：** 手动修复按钮已从列表、行内模型配置和编辑表单移除。每次写入 Codex 配置时，自动检测并补齐模型目录和桌面显示列表，包括使用供应商、确认编辑、同步连接、模型同步、默认模型、上下文和 Fast 修改。旧供应商无需打开旧修复标记。修复与配置同一事务提交，实际写入后仍弹“立即重启 / 稍后重启”；选项完整且文件无变化时不重复写入。未使用供应商只保存，下次使用时处理；取消不写入。恢复原配置还原接管前内容，不重新执行修复。下方版本说明保留为历史依据，当前操作见 [自动修复说明](automatic-reasoning-repair.md)。

> 0.4.0 操作更新：默认两字段、自动推荐模型，协议与认证放在高级设置；编辑和修复先保存在草稿，点击“保存并使用”后一起写入，取消不会写入。启动已自动检查配置目录。本文下方旧版操作与截图保留为历史记录，最新流程见 [简化流程](simple-flow.md)。


0.3.5 修正了 0.3.4 的遗漏：模型目录包含 `max`，不代表 Codex 桌面菜单一定显示 `max`。当前桌面端还会按“可用思考强度”设置过滤菜单，而该设置的默认值不包含 `max`。新版按钮同时修复模型目录和桌面显示设置。

uni-switch 不提供推理强度下拉框。具体强度由用户在 Codex 中选择，修复保留当前模型、强度、凭据、Fast、上下文与其他设置。

## 使用方式

升级到 0.3.5，打开 Codex 供应商的“编辑” → “更多选项” → “修复思考强度列表”。正在应用的供应商会立即修复所选目录中的模型目录和桌面显示设置；随后完全退出并重新打开 Codex。CLI 开启新进程或新会话。

0.3.4 用户需要再次点击按钮，或重新应用已开启修复的供应商，才能补上桌面设置。升级启动不会自动改写客户端文件。

已保存但尚未应用的供应商，按钮保存修复设置，应用该供应商时写入 Codex。新建供应商会显示“已准备修复”，点击“保存并应用”后生效。只保存时保留修复设置，取消新建表单时不会写入配置。按钮显示当前结果，失败显示原因。

## 两层修复

第一层是 `uni-switch-models.json` 的 `supported_reasoning_levels`。供应商 `/models` 经常不返回完整能力字段；Codex 根据模型目录生成 `model/list` 中的 `supportedReasoningEfforts`。按钮补齐 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`、`ultra`，保留原有描述、自定义能力和默认强度，不重复添加。旧配置没有目录时，基于已保存模型创建目录并附加 `model_catalog_json`。

第二层是 `config.toml` 中的桌面偏好：

```toml
[desktop]
enabled-reasoning-efforts = ["none", "minimal", "low", "medium", "high", "xhigh", "max", "ultra"]
```

代码保留已有数组顺序与有效值，追加缺项；原本包含 `persistent` 时继续保留，没有数组时也保留桌面默认的 `persistent`。这里只调整允许显示的选项，不设置当前 `model_reasoning_effort`，也不改主题等其他桌面偏好。

依据本机 Codex Desktop **26.930.3930.0** 的实际打包代码，默认允许显示 `low / medium / high / xhigh / ultra / persistent`，没有 `max`。桌面设置加载器优先读取 TOML 的 `[desktop]`；旧 `.codex-global-state.json` 偏好仅在 TOML 未指定对应项时迁移。因此此版本修复 TOML，无需修改全局状态文件或客户端安装文件。

`ultra` 在这份桌面版本中还受独立功能开关控制。补齐目录和允许显示的列表，仍不会绕过该开关。修复菜单元数据也不会增加模型或网关的实际推理能力，实际请求是否支持所选值由模型和供应商决定。

## 保存、恢复与兼容

供应商保存 `codexOptions.repairReasoningLevels`，后续刷新模型、保存和应用时补齐两层设置。旧数据默认关闭，打开过的旧表单不会覆盖已经生效的修复标记。

文件写入沿用备份、回读校验、外部变更检测、原子替换与中断恢复。修复后的供应商记录和文件管理状态在同一数据库事务中提交；文件未写完不会记录成功。桌面显示设置在首次接管时单独捕获，恢复时还原该时点的值；模型、凭据等原来已接管的字段仍恢复原始值，保留新增无关设置。切换到未开启修复的供应商后，恢复记录仍保留。

Codex 菜单对模型、强度、服务档位和显示偏好的修改不会误报为供应商路由冲突。API 地址、密钥和模型目录外部修改仍会阻止覆盖。显示数组类型或值异常时，整个修复失败且不写任何文件；当前 profile 覆盖模型或凭据库模式不兼容时，也显示具体原因。
