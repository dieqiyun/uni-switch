# 模型弹窗与计数 · 0.5.14

供应商列表中的模型名称与“管理模型”共用一个入口，点击打开独立模型弹窗。主列表不再插入模型配置区，多个供应商之间的布局保持一致。Codex、Claude 桌面与 Claude CLI 均使用此入口。

## 数量对应什么

原来的主列表显示数据库中已保存的数量；打开配置后自动同步上游模型，新模型默认勾选，却同样显示“已启用”，容易让人把草稿当成已保存配置。现在主列表与弹窗共用适用模型的判断规则；嵌入、图片等不适用模型不计入启用数量。

- 主列表的“已启用 N 个”：已保存的适用模型数量。
- 弹窗的“已选择 N / M”：本次草稿的选择数和可用数，分页与搜索不影响总数。
- 弹窗底部的“当前已保存 1 个，保存后启用 5 个”：直接说明自动同步后的数量变化。

例如导入的旧配置只有一个模型，上游返回五个时，弹窗默认勾选五个，并说明保存后启用五个。取消时数据库和客户端文件保持原样；确认后列表立即显示五个，正在使用该供应商时同时写入客户端。

## 弹窗操作

模型列表继续平铺显示勾选、默认模型与逐模型上下文。内容独立滚动，底部保存与取消固定可见。大量模型保留搜索、筛选和分页；设置默认模型时自动启用，Codex上下文默认256k。

弹窗具有可访问的标题和说明。打开时焦点进入模型区，Tab在弹窗内循环，Escape或取消关闭并回到原入口；点击遮罩保留选择，保存期间禁止重复提交和关闭。保存失败在弹窗内说明原因并保留草稿。实际修改Codex配置后继续提示立即或稍后重启。

## 验证

前端108项测试通过，包括原有一个模型、同步五个、取消保留一个、确认后变为五个，以及保存失败、逐模型上下文和保存后的重启提示。

原生桌面专项验证使用隔离数据库、配置目录和模拟上游，通过 `scripts/qa-model-dialog.mjs` 执行。覆盖数量、取消、真实Codex模型目录写入、键盘焦点、遮罩行为、85个模型分页、390px窄窗口和Axe检查。结果位于 `.qa/model-dialog/results.json`。
