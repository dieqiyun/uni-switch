# 供应商列表直接配置

0.5.14将下方的模型配置区改为独立弹窗，主列表统计已保存数量，弹窗显示本次选择和保存后数量，避免把自动同步的草稿当作已启用配置。见[模型弹窗与计数](model-dialog.md)。

0.5.12将供应商行内设置排列为带标签、固定列宽和基线的配置列，完整编辑表单用于API地址、密钥、协议与认证覆盖等连接信息。思考强度修复已改为自动处理，首次同步的上游适用模型默认全部勾选。

| 列表操作 | 保存方式 | 客户端生效 |
| --- | --- | --- |
| 默认模型 | 点击模型或管理模型打开弹窗，设默认后统一确认，未启用模型自动启用 | 当前目标正在使用此供应商时直接写入；其他供应商下次使用时生效 |
| 当前模型上下文 | Codex中按Enter或移开焦点保存，Escape取消 | 同上；默认256k，压缩值一起更新 |
| Fast | 保留原快捷开关 | 当前Codex写入；其他供应商下次使用时生效 |
| 思考强度显示 | 每次写入Codex配置时自动检测、补齐缺项，无手动按钮 | 和本次配置同一事务提交；未使用供应商下次使用时处理 |
| 模型配置 | 在独立弹窗展示勾选、搜索、逐模型上下文和同步 | 一次“保存并应用”或“保存模型配置”提交；取消不写入 |
| 余额刷新 | 余额旁的刷新按钮 | 不需要先展开余额详情，自动查询仍保留 |
| 名称 | 点击名称，Enter或勾号保存，Escape或X取消 | 仅修改供应商名称，不写客户端或提示重启 |
| 置顶 | 名称旁的图钉 | 立即记住列表偏好 |
| 同步其他客户端 | 其他已使用目标有待更新时显示 | 同步连接信息，保留各目标模型和专属设置 |

Codex每次实际配置文件修改后仍弹出“立即重启 / 稍后重启”。Claude桌面与CLI继续使用已有重启检测和提示。批量模型调整确认后一起写入，不为每次勾选弹窗；只保存未使用供应商、取消、失败及相同配置不新增重启提示。

快捷配置只提交模型相关字段，Rust从已保存供应商取回连接与密钥，不需要在前端读取真实密钥。写入前比较完整供应商快照；有待应用改动、外部配置冲突或列表已过期时停止，避免顺带应用其他编辑或覆盖新配置。数据库与当前客户端文件使用已有事务日志，失败保留原状态。修改Claude模型时保留已有Codex上下文。

同步只调用模型查询，不发送付费推理。2026-10-07修订：同步成功后不保留已从最新接口消失的模型，默认模型下架时自动选择仍可用的已启用模型；保存并应用后客户端目录与默认值一起替换。请求失败保留原列表。行内模型调整保持草稿，取消不会落盘。模型名称与模型数量共用一个入口，打开后自动同步最新列表，无重复下拉。见[同步移除下架模型](model-catalog-refresh.md)。

首次同步和新发现的适用模型默认勾选，默认模型仍单独推荐。已保存或当前草稿中主动取消的模型保持取消；刷新期间的勾选和上下文修改也会保留。全取消后不重新启用任何模型，确认时要求至少启用一个。分页仅影响显示，全部启用模型都会提交和写入。图片、音频、嵌入等不适用于当前编码客户端的模型继续标记为不适用，不计入可启用总数。

无框窗口保留。主列表在工作区滚动，模型弹窗内容独立滚动，底部确认与取消始终可见；窄窗口自动分行。按钮与输入提供中文辅助名称、键盘操作、错误关联和焦点恢复。

每次配置写入都会检测模型目录的 `supported_reasoning_levels` 和桌面的 `desktop.enabled-reasoning-efforts`，追加缺失的标准选项；旧供应商不依赖 `repairReasoningLevels` 标记。保留当前选中强度，不要求用户设置修复选项。恢复原配置还原接管前的设置，不再次修复；真实无变化不增加配置版本或重启提示。模型目录只有标准强度缺项时允许修复，地址、密钥、上下文、描述和其它模型元数据的外部变更仍阻止覆盖。

验证使用隔离数据库、客户端配置和模拟供应商。`scripts/qa-inline-models.mjs`嵌入原生完整流程，检查平铺模型确认选择、上下文确认与取消、名称修改、过期请求拒绝、行内草稿取消、自动补回缺失的max、余额刷新以及Claude桌面/CLI选择GPT模型。结果位于`.qa/ux-flow/results.json`。


布局按供应商信息、常用配置列、待处理事项排列。名称与置顶相邻，使用、编辑、删除固定在右侧，跨客户端同步另起一行。模型、上下文、Fast和余额都有标签及文字操作说明。见[供应商布局与对齐](provider-layout.md)。
