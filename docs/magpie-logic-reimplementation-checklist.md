# uni-switch 参照 Magpie 逻辑复现：整改清单

日期：2026-11-07。原始整改路线图。供应商查询、模型资料、双向推理/SSE、配置生成、原子文件事务和 SQLite 执行已接入 Go；Rust 仍保留原生与业务编排边界。最新逐项状态、删除项和验收限制以 [能力对齐清单](magpie-capability-alignment.md) 为准，下面的计划项不代表全部扩展功能已实现。

本地审阅基线：uni-switch v0.5.27，提交 `dab9242d63e1d7f5b22e775775280f27af31c032`。
Magpie 审阅基线：提交 `665b9aff126e26eb5fa8931b7395feb6002185f3`。该提交用于源码分析，不表示其中全部实现都应原样采用。

## 1. 目标与实施方式

按维护者要求，阅读 Magpie 的底层代码及测试，提取可验证的处理逻辑，用我们自己的 Go 代码重新实现业务底层，保留现有 React / TypeScript 界面和必要的 Tauri 原生壳。协议转换、流式处理、模型与能力、请求路由、余额额度、客户端适配等业务逻辑最终由我们自己的代码承接。

目标业务后端采用 Go；当前保留 Tauri / Rust 窗口壳及尚未迁移模块，前端继续采用 React + TypeScript。产品不依赖 Magpie 可执行程序、它的 Go 核心、本地管理接口或数据目录。新增 Go 1.26+ 构建要求，CI 固定 Go 1.26.8；我们自己的 Go 核心由源码编译并嵌入桌面程序，用户不需要安装 Go。

复现以“输入、状态变化、上游请求、输出、异常和取消行为”一致为目标，不逐行机械翻译 Go。无法确认的逻辑先列缺口；确定的上游缺陷不照搬。我方差异要注明原因和测试依据。

本轮已将桌面模型发现、协议识别、模型同步和自动余额查询接入 `backend/` 下自己的 Go 核心，并将资料目录、最终合并和用户覆盖从原 Rust/TypeScript 模块移入 `backend/internal/modelmeta/`，详见 [Go 后端说明](go-backend.md) 和 [模型资料来源对照](model-metadata.md)。2026-11-07 后续变更已将两方向协议转换、SSE、工具/思考续接、压缩、模型路由、原子文件事务、SQLite 执行及六类客户端配置生成接入 Go。本地监听、快照/确认编排、路径检查和保留注释的 TOML 编辑也已迁入 Go，Rust 保留窗口、系统集成及 IPC 壳。最新功能取舍与验收以 [能力对齐清单](magpie-capability-alignment.md) 为准；本阶段未发布。

## 2. 先明确当前问题

本地已有双向转换、SSE、工具续接、思考签名、上下文压缩和配置保护，也已经有相应测试。本清单不把这些能力当作从零缺失；整改重点是统一分散的规则、补全错误边界，并让已修复问题持续接受回归验证。

已知历史问题的依据是现有 CHANGELOG、审计文档及回归测试；模块耦合和规则重复属于需要核实的结构风险，不等于每个模块都已确诊故障。当前仍在发生的 Bug 应先收集最小复现，再确定优先级，不能仅凭功能相似认定 Magpie 已解决。

每个待复现模块必须产出四项内容：

1. **来源对照**：固定 Magpie 提交、文件、函数和相关测试；记录本次实际读过的分支。
2. **行为说明**：输入、内部状态、正常分支、失败分支、取消及重试条件。
3. **Go 实现与差异记录**：放在一个明确模块中，说明保留、改变或不支持的行为。
4. **验收证据**：固定样例、异常样例、历史 Bug、隔离客户端链路的结果。

只有文档或界面宣称支持、未读到核心分支和测试的内容，标为“待核对”，不计为逻辑复现完成。

## 3. Go 侧目标结构

```text
React / TypeScript：表单、草稿、显示和操作反馈
  → Tauri / Rust：窗口、系统集成和 IPC
  → 版本化管道：明确的命令、ID、大小限制及错误结构
  → Go 应用服务：供应商、配置事务、模型同步、诊断查询
  → Go 请求处理主链路
      ├─ 入口鉴权与已应用配置快照
      ├─ 客户端协议解码
      ├─ 统一内部消息 / 工具 / 思考 / 用量表示
      ├─ 模型解析、上游选择、能力与参数适配
      ├─ 同协议直通或目标协议编码
      ├─ HTTP 生命周期、SSE 和错误状态机
      └─ 回复编码、请求记录、计费用量
```

这是本项目的建议分层，不声称 Magpie 使用完全相同的类型或目录。Go 新模块按完整链路逐步接替现有 `bridge/`；存量 Rust 在验收前保留作参考，避免按目录一次清空。统一内部表示须保留协议专有扩展与 opaque 数据，避免抽象时丢失功能。

前端不承担第二套模型能力、协议路由、思考档位或余额计算规则；后端返回可展示的结果、来源和限制。

### P0 必须继承的历史回归

- 自定义 API 前缀被追加错误 `/v1`，以及 Claude 地址出现 `/v1/v1/messages`。
- Claude 模型 ID 被统一改成无关别名，档位请求误落默认模型，`[1m]` 信息丢失。
- assistant 结尾触发 prefill 拒绝，自动续接记录不能在下一轮恢复。
- 中途 system/developer 被移动，改变签名前历史；最低思考、独立 effort、空正文签名丢失。
- 工具 JSON 分片、命名空间、`apply_patch` 原始参数、工具结果回传和签名回放异常。
- 中文 SSE 分片、CR/BOM、事件跨块累积、截断和正常结束混淆。
- 多次上游请求的客户端上下文计数与计费用量不能混为一份：分别验证对客户端报告的口径和内部记录的口径。

每一项都需要本地固定样例。新增缺陷先做“旧代码能复现失败、新代码通过”的证据；已通过的历史场景保持通过，不为制造红灯而改变正确实现。

## 8. 对照测试方法

1. **协议样例**：从固定上游测试、公开协议资料和本地历史回归中提取脱敏输入及预期。记录上游测试意图，不仅复制最后 JSON。
2. **逐分支对照**：核对正常、空值、错误、取消、超时、重试及未支持内容；明确什么应原样保留，什么必须拒绝。
3. **旧/新实现对比**：同一合成输入分别验证；稳定字段精确比对，角色顺序、工具关系、签名、结束和用量语义另加断言，不为让结果相同而忽略关键字段。
4. **流式分片测试**：将同一合法事件流按不同字节位置拆分，结果应相同；结合中途取消、事件缺失、截断、重复结束和非法 JSON；不能只测一次 HTTP 块划分。
5. **故障注入**：构造限流、鉴权失败、上游已处理但连接断开、配置第二文件失败、确认期间变更等情况，验证请求数、回退、状态和恢复，而不只检查最终回复。
6. **客户端闭环**：在隔离目录启动真实客户端，用本地模拟上游验证模型菜单、真实请求、工具执行和后续对话。网络转发成功与用户流程成功分别签收。

如需运行 Magpie 作为行为对照，仅在另行准备的隔离测试环境执行，不成为产品运行或构建依赖。上游输出与公开协议、已有正确行为冲突时，先查明原因，不机械追求字节一致。
