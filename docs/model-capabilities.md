# 模型能力与连接测试

适用范围：当前工作树，尚未发布。返回 [教程](tutorial.md#models) 或 [项目首页](../README.md)。旧发布版的“默认开放”和四维验证说明不适用于本次 Go 实现。

## 资料来源与优先级

上下文、最大输出、图片输入、接口和思考档位由我们自己的 Go `modelmeta` 处理：解析实时上游条目，匹配 models.dev 目录，再按固定 Magpie 版本规则合并用户设置。详细字段和来源见 [模型资料说明](model-metadata.md)。Rust 和前端消费同一最终结果。

能力分为未知、明确支持和明确不支持。未知不自动声明支持，实时图片 `false` 不会被目录猜测改成 `true`，用户已保存的显式覆盖继续保留。刷新保留仍存在模型的启用选择、手动上下文和手动思考格式，不接纳上游返回的伪造用户覆盖。

模型列表不再有图片或并行工具勾选项；这不表示全部默认开放。工具、结构化输出和并行工具并非所有上游目录都会提供的通用事实，不能只凭名称或 HTTP 200 宣称已经支持。协议转换仍处理这些请求形状，实际供应商支持情况取决于最终资料及 API。

## 如何使用

1. 打开供应商的模型配置，刷新并选择启用模型和默认模型。
2. 按需要设置上下文和转换请求的思考格式。“自动”消费已解析资料；手动设置属于用户覆盖。
3. 当前供应商选择“保存并应用”，其他供应商可先保存，下一次应用时写入客户端。
4. 按提示重启对应客户端；旧会话可能保留模型目录或不兼容的思考记录。

未知上下文的 256k 仅为界面/客户端回退值，不写成上游事实，也不会扩大模型容量。Codex 八档菜单用于选择，实际请求按模型的上游档位映射，多个菜单项可能对应同一上游档位。

## 思考、历史与压缩

adaptive、预算思考、DeepSeek 和 OpenAI 参数由 Go 网关按最终模型档案生成。单独的 Messages `output_config.effort` 不自行开启 thinking。中途 system/developer 在原位置改成 user `<system-reminder>`，不再有每模型 inline-system 开关。

签名和 opaque reasoning 维持协议归属及连接/模型隔离；更改账号、模型或早期历史仍可能使上游签名失效。旧 Rust continuation/reasoning 容器不被当作新 Go 格式发送，涉及旧记录的会话需新建。转换模型使用 `/responses` 内的 `compaction_trigger`，独立 `/responses/compact` 明确返回 400。详见 [Go 后端说明](go-backend.md)。

## 单次模型连接测试

在详情中选择接口并明确确认可能计费后，发送一次合成 `hi` 请求，最多 16 输出 Token。不重试、不发送会话或文件、不执行工具，不进行图片或流式验证。结果为本次连接可用、不可用或待确认；成功不等于能力认证。

已移除原来最多 256 输出 Token 的文本/图片/工具/流式四维验证和观察文件写入。旧观察数据不参与能力合并；升级不主动删除用户数据目录中的旧文件。

## 资料更新与配置保护

公开目录改用 models.dev `api.json` / `models.json`，每小时检查，缓存满 24 小时刷新；失败保留已有有效缓存。目录没有发布者签名，缓存 SHA-256 只用于识别内容。原 Ed25519 签名资料权威链已退出当前运行路径，历史维护说明见 [签名资料维护](model-registry-maintenance.md)。

更新目录本身不写客户端配置。应用和恢复仍校验受管快照，保护外部修改，保留备份、冲突确认和多文件失败回滚。只有与上次应用快照相符的受管内容可以自动修复。

本次验收使用合成凭据和本地模拟供应商；真实付费上游和各平台原生客户端范围见 [能力对齐清单](magpie-capability-alignment.md)。
