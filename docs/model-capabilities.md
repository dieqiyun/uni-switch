# 模型能力与默认开放策略

适用范围：当前工作分支，尚未发布。返回 [教程](tutorial.md#models) 或 [项目首页](../README.md)。历史版本的手动能力设置见相应发布标签。

## 如何使用

图片输入和并行工具调用默认开启，模型列表不再显示能力勾选、待确认勾选提示或恢复能力按钮。模型是否启用、默认模型和上下文仍可单独配置。保存并应用后，按提示重启对应客户端；未使用的供应商在下次应用时生效。

旧配置中的 capabilityOverrides、上游返回的 false 和未知型号都不会关闭这些入口。刷新模型时清除废弃的能力覆盖，保留启用选择、上下文和手动思考格式。上游与官方资料仍按原值显示，供判断真实支持情况；默认开放表示允许发送请求，不代表模型已经通过能力验证。

Codex 目录为模型写入 text + image 和并行工具支持。OpenAI → Claude 转换服务不再因旧图片、工具或结构化输出能力声明在本地拒绝请求；WorkBuddy 的图片、工具声明以及 DSH 的图片输入也使用默认开放规则。客户端明确发送的串行工具要求继续生效。

## 思考格式与新 Claude 模型

[共用模型档案](../src/content/model-capabilities.json)记录接口声明、思考格式、档位和上限；手动协议覆盖、上游元数据和内置资料仍按逐字段优先级合并。默认开放能力不会把 Messages、Responses 和 Chat Completions 当成同一种协议。

- Opus / Sonnet 5.5 和 Fable 5.1 补齐 adaptive 档案，转换不再误用 budget_tokens。Opus 默认 effort 为 medium，Sonnet / Fable 为 high；转换有显式档位时继续映射用户选择。
- 这些模型的 adaptive 转换请求使用 display: summarized，保持思考和工具间进度可见。签名内容完整保存和回放，即使 thinking 正文为空或缺失也不会制造空摘要事件。
- Sonnet 5.5 的 none 映射为 between_tools + low，不添加该模式不接受的 display 或预算字段。Opus / Fable 无法关闭思考，none 返回明确错误。
- 这些模型拒绝强制工具选择；转换遇到 required 或指定工具时明确提示，不把“必须调用”悄悄改成 auto。合成工具验证采用 auto，仍要求响应中真实出现指定工具和参数。
- 旧 Claude 4.5 的预算思考保留。未知私有别名需要明确的上游思考格式或手动覆盖，避免猜错协议。恢复自动思考格式请在思考模式下拉框选择“自动”。
- 结尾的 Claude [1m] 标记在资料匹配时被识别，避免带上下文标记的已知模型丢失思考档案。原生桌面配置仍将标记转换为 supports1m，模型路由继续保留上游真实 ID。

Claude → OpenAI 转换也保留独立的 output_config.effort 和 adaptive 默认档位。disabled / between_tools 映射到目标声明的最低档位；未声明档位时保守使用 low，不能保证完全关闭思考。DeepSeek 使用独立的 none 关闭控制。OpenAI 协议没有 Claude between_tools 的完全等价模式，因此最低档位只代表目标侧的最小思考设置。

对明确支持中途 system 消息的模型，后续 system/developer 更新保留在 user（包括工具结果）之后、assistant 之前或请求末尾；不会移到初始 system 并改变旧签名的前缀。非法位置返回明确提示，旧模型继续使用原有顶层 system 格式。自动插入的 user 续接指令通过空摘要 reasoning 记录随普通/流式响应返回，后续完整历史回放会还原该消息；客户端需保留 encrypted_content，丢失记录的旧会话需要新建。

Codex 模型目录仍提供现有八档思考菜单；档案用于展示与请求映射，不缩减菜单。上下文仍按既有同步规则保留旧值或采用 256K 默认值，档案中的 1M 不会擅自覆盖用户上下文。

## 默认开放后的兼容性

| 情况                         | 使用影响                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 发送图片                     | 请求体积、上传耗时和可能的 Token 费用增加；开启声明本身不会自动上传图片。                                          |
| 一轮多个工具                 | 客户端可能并行执行，涉及写文件、提交或有先后依赖的操作需由客户端正确调度；显式串行要求继续保留。                   |
| adaptive 思考                | 新模型即使未显式请求也可能消耗思考 Token；显示摘要不等于关闭思考。                                                 |
| 切换模型或账号               | 先前思考签名可能不兼容，可能被丢弃或返回 400；需要时新建会话。                                                     |
| 重写早期消息、系统提示或工具 | 新模型可能对签名前的历史做绑定校验。原生 Claude 由客户端维护；转换接入依赖稳定历史，默认开放不能修复被修改的历史。 |
| 旧会话或未重启客户端         | 可能仍缓存旧能力目录或模型配置；保存并应用后重启并用新会话核验。                                                   |

上游不支持能力时返回的错误照常展示。不会通过更改真实模型名、偷偷换模型、丢弃签名或自动重试推理来掩盖错误。

## 显式接入验证

单个模型的“接口、思考参数与接入验证”保留。验证需要用户明确接受可能计费，每次只发送一个合成文本、32×32 图片、工具声明或流式请求，最多请求 256 输出 Token；不执行工具、不重试、不发送会话或文件。只有回复语义匹配且流正常结束才标记本次通过，HTTP 200 本身不算验证成功。

始终思考的模型可能先耗尽 256 Token，导致没有可验证文本；此时结果保持“待确认”，不能据此判定能力不支持，也不会扩大验证费用上限。观察结果保存在私有数据目录的 model-verifications，不含密钥或响应原文；浏览器预览不能发起付费验证。

## 资料更新与配置保护

签名资料更新继续要求 HTTPS、Ed25519、版本递增和严格格式。当前 release-config.json 的 modelRegistry 为 null，没有生产远程资料源，界面继续明确提示未配置。资料更新不会自动写客户端配置。维护步骤见 [签名资料维护](model-registry-maintenance.md)。

启动时只修复与上次应用快照相符的受管 Codex 目录，继续通过事务、备份和修订机制写入。外部修改、损坏文件或冲突不被自动覆盖。Fast、模型保存及档位修复使用同一能力策略，避免旧 text-only 标记恢复。恢复原配置仍使用最初接管快照。
