# 上游模型默认全选 · 0.5.10

首次接入无需逐个勾选。自动同步上游模型列表后，适用于当前客户端的模型默认全部启用；软件单独推荐一个启动默认模型，其他启用模型仍会写入客户端配置。

## 选择规则

- 添加供应商的首次同步默认全选，Codex、Claude Code桌面端和Claude CLI一致。
- 行内模型配置与完整编辑的后续同步，发现的新模型自动勾选。
- 已保存或当前草稿中主动取消的模型保持取消，刷新不重置用户的选择。
- 刷新请求期间调整模型或上下文，响应返回后保留最新草稿，避免覆盖修改。
- 全部取消后，再次刷新不会强行启用默认模型。保存仍要求至少一个启用模型。
- 2026-10-07修订：同步成功后只保留上游最新返回的模型。下架模型及其上下文从草稿移除；原默认模型下架时自动选择仍启用的可用模型，确认保存后替换客户端列表。见[同步移除下架模型](model-catalog-refresh.md)。

每个Codex模型默认上下文256k，保留已有模型设置。图片、音频、嵌入等不适用于编码客户端的模型继续标记为不适用，界面计数只以可启用模型为分母。Claude原生桌面配置只接受可识别的Claude模型；OpenAI转换模式仍支持其它适用模型。

分页和搜索仅改变展示。供应商返回85个适用模型时，即使首屏只显示40个，全部85个仍默认勾选；确认后全部写入供应商记录和Codex模型目录。

模型选择沿用草稿与确认流程，取消不写入。每次实际修改Codex配置仍自动修复思考强度并提示立即/稍后重启。新模型默认启用不意味着刷新查询直接改写客户端，仍需确认保存。

## 验证

前端测试覆盖两个协议、三个客户端的首次全选、默认模型推荐、刷新期间的修改保留、新模型自动启用、已保存取消项保留、全取消后刷新、站点变化和迟到响应保护。原生流程验证两模型首次写入及85个上游模型全部写入Codex目录，分页不漏模型。

0.5.10验证结果：105项前端测试、109项Rust测试通过（1项辅助进程按设计忽略）；41组原生流程通过，18处Axe检查无违规，前端运行错误0。TypeScript、Vite、Clippy、Rust格式检查和Windows正式构建通过，交付文件SHA256校验一致。

结果位于 `.qa/ux-flow/results.json`。Windows拒绝为隔离窗口获取鼠标焦点，本次原生鼠标拖动未执行；正式包的单实例启动检查因用户0.5.9仍在运行而跳过，保留该进程。本次模型选择与文件写入在隔离原生程序中验收，未修改用户真实配置。
