# 供应商列表的信息层级与对齐 · 0.5.12

0.5.14保留以下列布局，并将“管理模型”改为独立弹窗，避免展开模型时撑长供应商行。数量区分已保存配置与本次选择。见[模型弹窗与计数](model-dialog.md)。

供应商列表按“连接信息与操作 → 带标签的配置列 → 待处理事项”排列。每个供应商采用相同列宽和对齐规则，不用卡片包住每个设置，也不增加下拉选择。

第一行显示供应商名称、名称旁的置顶和API地址。使用、编辑、删除固定在右侧，删除有文字名称；跨客户端同步不再挤占这一操作区。正在使用的供应商保留浅色背景和已应用状态。

Codex配置区有四列，各列标签、数值和辅助说明分别对齐：

| 标签 | 显示内容 | 操作与提示 |
| --- | --- | --- |
| 默认模型 | 当前目标的默认模型ID | 下方显示已保存的启用数量和“管理模型”，点击打开模型配置弹窗 |
| 上下文长度 | 默认模型对应的k值 | 下方提示修改后自动保存；Enter或移开焦点保存，Escape取消 |
| Fast 加速模式 | 开关与已开启/已关闭文字 | 说明需要供应商支持、可能增加费用；Claude转换显示暂不支持 |
| 账户余额、密钥额度等 | 金额和单位，保留真实额度类型 | 下方明确显示“详情”和“刷新”，默认仍自动查询 |

Claude桌面端和CLI显示默认模型与余额两列。窄窗口自动排列为两列并将操作区放在配置下方，长模型ID截断展示，完整ID保留在按钮提示中。

其他客户端有待更新连接时，另起一行显示“其他客户端的连接配置有待更新”与“同步其他客户端”。当前客户端的重启需求或外部冲突继续单独提示。正常状态下不会多显示一段重复成功说明。

模型弹窗内直接展示模型列表；添加和编辑中的模型与高级设置保持展开。默认全选、取消不写入、批量确认、逐模型上下文、自动思考强度修复和配置写入后的重启提示继续使用原有机制。

## 布局验证

列表样式集中在`src/provider-list.css`，删除旧文件中重复的供应商布局规则，避免宽度变化或状态变化时互相覆盖。`scripts/qa-provider-layout.mjs`在真实Tauri/WebView2窗口测量供应商的标签和数值基线、列起点、列宽、名称与置顶之间的距离，以及同步按钮是否侵入主要操作区。

完整桌面流程继续检查390px布局、等效125%/150%/200%缩放、键盘及焦点、两协议三客户端配置、取消草稿、85个模型完整写入与三端重启。结果位于`.qa/ux-flow/results.json`，未执行项目单独记录。
